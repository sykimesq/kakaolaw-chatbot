# 카카오톡 법률사무소 챗봇 — 되묻기 시나리오 상세 설계

> 작성일: 2026-08-07
> 상태: 초안 (사용자 리뷰 대기)
> 관련 문서: `2026-08-07-kakao-law-chatbot-design.md` (상위 설계)

## 1. 개요

되묻기(질의 수집) 시나리오는 **LLM 동적 질문 방식(방식 B)** 을 채택한다.
문의자의 답변을 보고 LLM이 즉석에서 다음 질문을 생성한다.

> ⚠️ **LLM은 반드시 "되묻기 에이전트"로만 동작한다.**
> 법률 답변/자문/예측/판단을 절대 생성하지 않는다.
> 모든 응답은 "추가 정보 요청" 형태여야 한다.

## 2. LLM 동작 원칙 (HARD 규칙)

시스템 프롬프트에 반드시 포함되는 불변 규칙:

### 2.1 금지 (LLM이 절대 하지 않는 것)
- ❌ 법률 판단/의견/예측 제공
- ❌ 구체적 법 조항 해석
- ❌ 사건 결과 예측 (이기나 지나, 유죄/무죄 등)
- ❌ 어떤 답변이든 "조언"으로 해석될 수 있는 내용
- ❌ 문의자 질문에 최종 답변을 주는 것

### 2.2 허용 (LLM이 하는 것)
- ✅ 문의자의 질문 내용 이해
- ✅ 부족한 정보 파악
- ✅ 정보 수집을 위한 질문 생성 (되묻기)
- ✅ 문의자 답변 요약/구조화
- ✅ "상담 접수" 흐름으로 안내

### 2.3 필수 응답 템플릿
LLM의 모든 되묻기 응답은 다음 구조를 따른다:

```
[공감 한 줄] (문의 내용 인지)
[되묻기 질문 1개] (부족한 정보 하나만 물어봄)
[안내] 필요 시 "상담 접수로 진행하면 됩니다" 유도
```

한 번에 **질문 1개만** 한다. (모호성 낮추기 + 문의자 부담 최소화)

## 3. 되묻기 수집 항목 (공통)

LLM이 어떤 정보를 모으는지, 분야 공통으로 수집하는 항목:

| 항목 | 질문 예시 |
|------|-----------|
| 상담 분야 | "어떤 사건에 대해 문의하시나요? (가정/부동산/채권채무/형사/노무/교통사고)" |
| 문의자 입장 | "문의하시는 분은 어떤 입장이신가요? (당사자/가족/제3자 등)" |
| 사건 경위 | "어떤 일이 있었는지 간단히 말씀해주세요." |
| 현재 진행 상황 | "현재 소송/조정/협의 등 진행 중인 것이 있나요?" |
| 원하는 것 | "도움을 받아 해결하고 싶으신 것이 무엇인가요?" |
| 구체적 수치 | 금액/일시/기간 등 필요한 수치 |

## 4. 분야별 추가 질문 가이드

LLM이 분야에 따라 추가로 물어볼 수 있는 항목:

### 4.1 가정 (이혼·상속·가사)
- 이혼: 협의 가능 여부, 자녀 유무, 재산/위자료, 이혼 사유
- 상속: 상속인 관계, 상속 재산 종류, 유언장 유무, 상속 분쟁 여부
- 가사: 가정폭력/아동 등, 긴급성

### 4.2 부동산
- 매매/임대차/명의신탁 구분
- 계약 진행 단계 (계약 전/계약 후/중도)
- 분쟁 상대방 (매도인/임대인/중개업자)
- 손해 금액, 계약금/중도금

### 4.3 채권/채무
- 채권자/채무자 입장
- 금액, 이자, 변제 기한
- 현재 변제 상황, 연체 여부
- 회생/파산 고려 여부

### 4.4 형사
- 고소인(피해자)/피의자(피고인) 입장
- 사건 유형 (사기/폭행/성범죄 등)
- 수사 진행 단계 (경찰/검찰/기소)
- 긴급성 (구속 여부)

### 4.5 노무
- 근로자/사업주 입장
- 사건 유형 (해고/임금체불/부당노동 등)
- 재직 상태, 근무 기간
- 체불 금액, 해고 사유

### 4.6 교통사고
- 당사자/가해자/피해자 입장
- 사고 경위, 피해 정도 (부상/재산)
- 보험 처리 여부, 과실 여부
- 형사처벌/손해배상 여부

## 5. 완료 판단 (모호성 낮춤 기준)

LLM이 되묻기를 그만할 시점 판단. 다음이 충족되면 수집 완료:

1. **상담 분야** 확인
2. **문의자 입장** 확인
3. **사건 경위** 파악 (언제/무엇이/어떻게)
4. **원하는 것** 확인
5. **구체적 수치** (해당 분야에 필요시) 확인
6. 문의자가 더 답변할 내용이 없다고 함

위 항목이 모이면 → **질의 요약 생성 → 변호사 알림톡 전달** 단계로 이동.

## 6. 질의 요약 포맷 (변호사에게 전달)

수집 완료 시 LLM이 아래 구조로 요약을 생성하고, 문의자 연락처와 함께
변호사에게 알림톡으로 전송한다.

```
📋 법률 상담 질의 접수
─────────────────────
접수일시: 2026-08-07 14:32
문의자: 김○○ (010-1234-5678)

[분야] 가정 (이혼)
[입장] 당사자 (배우자)
[사건 경위]
배우자 부정 사실 확인, 별거 6개월. 협의 이혼 시도했으나
배우자 거부로 재판 이혼 고려 중.

[현재 진행 상황]
별다른 법적 절차 없음. 협의 시도만 했음.

[원하는 것]
자녀 양육권과 재산분할 방법 문의. 위자료 가능 여부.

[추가 사항]
문의자가 8월 내 상담 희망.
─────────────────────
[확인] [예약 연결] [완료]
```

- 문의자 연락처 포함 (변호사가 직접 회신 가능)
- 버튼: [확인] / [예약 연결] / [완료]

## 7. 예외 처리

### 7.1 문의자가 긴급 상황 호소
"구속", "긴급", "내일 재판", "위험" 등의 신호 감지 시:
- 되묻기를 중단하고 **즉시 접수 처리**
- 요약에 "[긴급]" 표시 → 변호사에게 우선 알림

### 7.2 문의자가 분야/입장을 명확히 못 박지 못함
- "잘 모르겠다" 응답 시: 가장 근접한 분야 선택을 유도하거나
  "구체적으로 어떤 일이 있었는지"로 되물음

### 7.3 LLM이 법률 답변을 시도할 때 (안전장치)
- 시스템 프롬프트 HARD 규칙(§2) 적용
- LLM이 답변을 생성하려 하면 "상담 접수로 진행해주세요"로 전환하는
  가드 레일 구절을 프롬프트에 포함
- 생성 응답을 사전 검증 필터로 감사 (법률 판단 키워드 감지 시 차단)

## 8. 구현 참고

- 되묻기 LLM은 **백엔드 서버**에서 구동 (오픈빌더 스킬 → 백엔드 LLM API 호출)
- LLM 모델: 법률 답변 유도에 안전한 프롬프트 제어가 가능한 모델 사용
- 질의 요약 생성은 별도 호출 (수집 완료 시 1회)
- 모든 대화는 로그 저장 (감사/추적 목적)
